# Практическая работа № 4. Потоки

## Вариант B

Цель: сравнить вычисления и сетевой ввод-вывод при последовательном
выполнении, использовании четырёх потоков и четырёх процессов.
Показать различие памяти потоков и процессов.

## Среда и методика

Работа выполнена в Linux через WSL.
Сведения о системе, версии Python и процессоре сохранены
в environment.txt. Значение nproc приведено в таблицах и обозначает
число доступных логических процессоров.

Для каждого способа выполнено три измерения.
Основной результат — медиана времени.
Время измерялось через time.perf_counter().

В numbers.txt находятся 10 000 000 целых чисел от 1 до 10 000 000.
Данные сгенерированы заранее.
Для вычислительного опыта файл предварительно загружен в память.
Генерация, чтение файла и преобразование строк в числа
не входят в измеренное время суммирования.

Вычисления выполняются Python-циклом.
При параллельном выполнении массив разделён на четыре части.
Каждый работник вычисляет свою частичную сумму.
Создание работников, ожидание и получение результатов включены
в измеренное время.

В вычислительном опыте multiprocessing использует fork.
В сетевом ProcessPoolExecutor используется spawn.

Для сетевого опыта подготовлены 20 URL локального HTTP-сервера.
Каждый файл содержит 65 536 байт.
Сервер обслуживает запросы параллельно и искусственно задерживает
каждый ответ на 0,2 секунды.
Измеряется получение полного содержимого ответов в память,
без сохранения на диск.

Ускорение рассчитано как отношение медианы последовательного
способа к медиане рассматриваемого способа.

## Наблюдения по моим измерениям

Измерения выполнены при 12 доступных логических процессорах
(nproc = 12). Каждый способ запускался три раза.

В вычислительной задаче медиана одного потока составила 0,475072 с,
четырёх потоков — 0,508605 с, четырёх процессов — 0,206604 с.
Самым быстрым способом оказались четыре процесса:
ускорение относительно одного потока составило 2,30 раза.

Четыре потока не ускорили вычисления и оказались немного медленнее
одного. Это согласуется с ограничением GIL в CPython:
потоки одного интерпретатора не выполняют наш Python-цикл
одновременно на нескольких ядрах.
Процессы могут выполнять вычисления параллельно, и в этом опыте
выигрыш перекрыл расходы на их создание и получение результатов.

В сетевой задаче медиана последовательного выполнения составила
4,042726 с, четырёх потоков — 1,015386 с,
четырёх процессов — 1,172021 с.
Самым быстрым способом оказались четыре потока:
ускорение относительно последовательной загрузки составило
3,98 раза. Четыре процесса дали ускорение 3,45 раза.

Потоки позволили перекрывать ожидания ответов сервера.
Процессы также ускорили загрузку, но оказались медленнее потоков,
что согласуется с дополнительными расходами на запуск
отдельных интерпретаторов.

По результатам этой работы для вычислительной задачи выгоднее
использовать процессы, а для сетевой задачи — потоки.
Сетевой результат получен на локальном сервере с искусственной
задержкой ответа 0,2 секунды на каждый запрос.
