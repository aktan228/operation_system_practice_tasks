# Практическая работа по предмету «Проектирование операционных систем»
## Вариант B

### 1. Среда выполнения

Работа выполнена в Ubuntu 26.04 LTS, установленной в WSL.
Версия ОС проверена командой cat /etc/os-release.

### 2. Пользователи и группы

Создан пользователь student2.
Создана группа developers.
Пользователь student2 добавлен в developers командой:

sudo usermod -aG developers student2

Членство в группе проверено командой id student2.

### 3. Общий каталог

Создан каталог /srv/shared.
Владелец каталога — root, группа — developers.
Установлены права 2775: drwxrwsr-x.

Владелец и члены группы могут просматривать каталог,
создавать и удалять записи в нём.
Остальные пользователи могут просматривать каталог и обращаться
к файлам внутри, но не могут создавать и удалять записи.

Бит setgid обеспечивает наследование группы developers
новыми файлами и подкаталогами.

Чтение содержимого файлов дополнительно зависит от прав самих файлов.

### 4. Создание файла и попытка удаления

От имени student2 создан файл /srv/shared/student2.txt.
Права файла — 644, владелец — student2, группа — developers.

Основной пользователь не входит в developers.
При попытке удалить файл командой rm без sudo получена ошибка
Permission denied.

Причина: основной пользователь имеет на каталог права r-x,
но для удаления файла необходимы права записи и прохода
на родительский каталог.

Если пользователь входит в developers, при текущих правах
каталога он может удалить чужой файл: sticky bit не установлен.
Право записи в сам файл для его удаления не требуется.

### 5. Чем su отличается от sudo

su запускает оболочку или команду от имени другого пользователя.
При обычном переключении через su запрашивается пароль
целевого пользователя.

Например, su - student2 открывает оболочку student2
с окружением, похожим на окружение при входе в систему,
и переходом в его домашний каталог.
Без имени пользователя su по умолчанию выбирает root.

sudo запускает разрешённую политикой команду от имени другого
пользователя, по умолчанию — root.
Обычно sudo запрашивает пароль вызывающего пользователя.
Повторный запрос может временно не появляться из-за кэширования
успешной аутентификации.

Например, sudo mkdir -p /srv/shared создаёт каталог
с правами root, если пользователю разрешена такая команда.

sudo также позволяет открыть административную оболочку,
например командой sudo -i.

### 6. Почему в Ubuntu по умолчанию заблокирован вход под root

В Ubuntu по умолчанию заблокирован пароль root.
Это препятствует прямому входу под root с использованием пароля.

Административные действия выполняются через sudo.
Такой подход уменьшает необходимость постоянно работать
с полными правами, снижает риск случайного повреждения системы
и позволяет учитывать, кто запускал административные команды.

Учётная запись root продолжает существовать.
Блокировка пароля не запрещает авторизованному пользователю
получать права root через sudo.

### 7. Настройка Bash

В ~/.bashrc основного пользователя добавлены:

alias cshared='cd /srv/shared'
alias lshared='ls -la /srv/shared'
export OS_LAB_VARIANT="B"

После открытия новой сессии проверено:

- cshared переводит в /srv/shared, что подтверждается командой pwd;
- lshared выводит содержимое общего каталога;
- echo "$OS_LAB_VARIANT" выводит B;
- дочерняя оболочка bash также получает эту переменную.
